# 自动交易系统 PRD 与技术架构

## 1. 项目定位

本项目第一阶段不是做全自动实盘交易机器人，而是做一个用于验证交易信号有效性的研究系统。

核心目标是把 HFD Pro 等信号源转化为可记录、可复盘、可评分、可验证的交易决策流程。系统先进行纸上交易，等信号组合在真实时间流中证明有正期望、较好 ROI、可接受回撤后，再接入交易所模拟盘，最后才进入小资金实盘。

一句话定位：

> 先证明策略有 edge，再让系统执行；先保护本金，再追求收益。

## 2. 核心原则

1. 不做历史图上的后验幻想，只记录实时信号快照。
2. 不用单一指标开仓，必须多信号组合确认。
3. 不以胜率为唯一目标，重点看正期望、盈亏比、Profit Factor 和最大回撤。
4. 不直接接实盘，必须经过纸上交易和交易所模拟盘。
5. 实盘默认关闭，必须手动开启，并受到风控闸门限制。
6. 每一次策略修改都要版本化，禁止频繁随意调参。
7. 不同币种不是同一种市场，必须按流动性和波动性分层处理。
8. 不同周期不是同一套参数，必须做短期、中期、长期联动。

## 3. 阶段路线

### 阶段 -1：历史数据回测与策略初筛

目标：

利用暗流 Pro 已经存在的历史数据，快速筛掉明显无效的信号组合，找出值得进入纸上交易的候选策略。

定位：

- 历史回测只用于策略初筛。
- 历史回测不能直接证明策略可实盘。
- 能通过历史回测的策略，必须再进入实时快照纸上交易。

原因：

暗流 Pro 的历史指标可能已经包含后续修正，尤其是趋势段、成本带、耗竭区间、订单块状态这类指标，历史图上看起来很准，不代表当时那一刻系统真的已经知道同样的信息。

历史回测要分两种：

| 类型 | 用途 | 可信度 |
|---|---|---|
| 静态历史回测 | 用当前接口返回的过去数据回测 | 中低 |
| 快照回放回测 | 用我们当时保存的信号快照回测 | 高 |

阶段 -1 可以做：

1. 拉取暗流 Pro 已有历史数据。
2. 对 9 个币种、3 个周期做历史样本分析。
3. 测试不同信号组合的胜率、盈亏比、最大回撤。
4. 找出候选策略。
5. 标记疑似重绘或后验依赖的信号。

阶段 -1 不允许：

1. 直接根据历史回测结果接模拟盘。
2. 直接根据历史回测结果接实盘。
3. 频繁调参直到历史曲线完美。
4. 忽略手续费、滑点、延迟。

进入阶段 0 的要求：

- 至少筛出 2-3 个候选策略。
- 每个候选策略必须有明确入场、止损、止盈、过滤条件。
- 每个候选策略必须标注可能的重绘风险。
- 每个候选策略必须进入实时快照验证。

### 阶段 0：信号研究与数据确认

目标：

- 确认 HFD Pro 信号接口稳定性。
- 确认信号是否存在重绘或盘中变化。
- 确认不同周期、不同币种的信号结构。

范围：

- 币种：BTC、ETH、SOL、BNB、LINK、DOGE、TON、HYPE、ZEC。
- 周期：短期、中期、长期。
- 周期映射：短期 = 30m，中期 = 1h，长期 = 4h。
- 信号源：HFD Pro 接口、交易所行情接口。

币种分层：

| 层级 | 币种 | 用途 | 默认风险 |
|---|---|---|---|
| 核心层 | BTC、ETH | 主策略验证、基准参考 | 低 |
| 主流层 | SOL、BNB、LINK、TON | 主要扩展交易池 | 中 |
| 高波动层 | DOGE、HYPE、ZEC | 验证爆发型和扫损型策略 | 高 |

周期职责：

- 短期，负责触发和入场。
- 中期，负责位置和结构确认。
- 长期，负责方向和大级别过滤。

输出：

- 信号字段说明。
- 指标分组。
- 信号快照样例。
- 重绘风险评估。

### 阶段 1：信号快照库

目标：

实时保存信号在当下的状态，避免未来复盘时受到后验数据污染。

系统每隔固定时间拉取：

- K 线数据。
- 当前价格。
- HFD 指标数据。
- 指标状态。
- 当前策略版本。

关键要求：

- 每条信号必须带采集时间。
- 原始响应必须保留。
- 派生特征单独存储。
- 后续策略只能使用当时已经存在的数据。
- 同一个信号要同时记录短期、中期、长期三个视角，避免单周期误判。

### 阶段 2：纸上交易系统

目标：

用真实时间流中的信号模拟交易，不接交易所下单。

功能：

- 模拟开仓。
- 模拟止损。
- 模拟止盈。
- 模拟手续费。
- 模拟滑点。
- 记录最大浮盈 MFE。
- 记录最大浮亏 MAE。
- 记录出场原因。

交易类型：

- 趋势回踩延续。
- 流动性猎杀反转。

第一版不做：

- 马丁格尔。
- 网格。
- 高频交易。
- 自动加仓。
- 多交易所套利。

### 阶段 3：策略评分引擎

目标：

把多个信号转成统一评分，只有高质量机会才允许纸上开仓。

初始评分模型：

| 模块 | 分数 | 说明 |
|---|---:|---|
| 长期方向一致 | 25 | 4h 趋势成本带、趋势撑压、机构均价一致 |
| 关键位置 | 25 | 价格接近成本区、筹码节点、清算区 |
| 短期触发 | 20 | 30m 出现猎杀、插针、结构确认 |
| 趋势耗竭支持 | 20 | 能量耗竭、趋势进度、资金阀值支持 |
| 盈亏比达标 | 10 | 预期盈亏比至少 1:2 |

决策规则：

- 75 分以上：允许纸上开仓。
- 60-75 分：只记录观察，不开仓。
- 60 分以下：忽略。

周期联动规则：

1. 长期决定方向，只在长期偏多时优先找多，长期偏空时优先找空。
2. 中期决定位置，必须靠近成本带、筹码区、清算区或 POC。
3. 短期决定触发，必须出现 sweep、收回、失衡、共振或反转确认。
4. 三个周期冲突时，以长期为主，中期为辅，短期只做过滤，不单独推翻方向。

### 阶段 4：复盘与策略微调

目标：

找出真正有效的信号组合，并过滤亏损集中的场景。

核心统计：

- ROI。
- 胜率。
- 平均盈利。
- 平均亏损。
- 盈亏比。
- Profit Factor。
- 最大回撤。
- 连续亏损次数。
- 单笔最大亏损。
- 期望值。
- 不同行情阶段表现。

微调原则：

- 每周统一复盘，不每天随意改参数。
- 每次只改一个主要变量。
- 每个策略版本至少跑满固定样本量。
- 新版本必须和旧版本横向对比。

进入下一阶段门槛：

- 至少 200 笔纸上交易。
- 至少 6-8 周真实时间数据。
- 扣除手续费和滑点后仍为正收益。
- Profit Factor 大于 1.4。
- 最大回撤在可接受范围内。
- 没有明显只适合单一行情的过拟合问题。

### 阶段 5：交易所模拟盘

目标：

验证工程执行可靠性，不以盈利为主要目标。

接入对象：

- OKX Demo Trading。
- Binance Spot Testnet。
- Binance Futures Testnet。

币种优先顺序：

1. BTC、ETH 先接。
2. SOL、BNB、LINK、TON 第二批接入。
3. DOGE、HYPE、ZEC 最后接入，只在风控稳定后开放。

验证内容：

- 下单是否准确。
- 止损止盈是否正确。
- API 错误是否处理。
- WebSocket 断线是否恢复。
- 是否会重复开仓。
- 仓位是否和系统记录一致。
- 手动停止是否立即生效。

### 阶段 6：小资金实盘

目标：

在极低风险下验证真实交易环境。

限制：

- 先允许 BTC、ETH、SOL、BNB、LINK、TON。
- DOGE、HYPE、ZEC 只在后续验证通过后逐步放开。
- 单笔风险控制在总资金的 0.1%-0.3%。
- 总实盘测试资金控制在总资金的 1%-3%。
- 默认逐仓。
- 禁止高杠杆。
- API Key 禁止提现。
- 开启 IP 白名单。

实盘停止条件：

- 达到单日最大亏损。
- 连续亏损超过阈值。
- API 出现异常。
- 价格跳变超过阈值。
- 系统记录仓位和交易所仓位不一致。
- 手动触发 Kill Switch。

## 4. MVP 范围

第一版只做以下内容：

1. HFD 信号采集。
2. BTC、ETH、SOL、BNB、LINK、TON、DOGE、HYPE、ZEC 行情采集。
3. 信号快照入库。
4. 两套策略模板。
5. 纸上交易撮合。
6. 交易日志。
7. 基础统计报表。
8. 策略版本管理。

第一版不做：

1. 实盘交易。
2. 交易所真实下单。
3. 复杂前端大屏。
4. 机器学习模型。
5. 自动调参。
6. 多用户系统。
7. 收费系统。

### 4.1 交易池与周期矩阵

系统不直接判断“这个币能不能交易”，而是判断“这个币在这个周期、这个策略、这个风险层级下能不能交易”。

交易池配置：

| symbol | 层级 | 默认开放 | 说明 |
|---|---|---|---|
| BTCUSDT | 核心层 | 是 | 市场基准，所有策略先验证它 |
| ETHUSDT | 核心层 | 是 | 第二基准，流动性好 |
| SOLUSDT | 主流层 | 是 | 波动更强，适合趋势和扫损策略 |
| BNBUSDT | 主流层 | 是 | 波动相对稳，适合趋势策略 |
| LINKUSDT | 主流层 | 是 | 中期结构经常更清晰 |
| TONUSDT | 主流层 | 是 | 需要额外关注流动性和滑点 |
| DOGEUSDT | 高波动层 | 观察优先 | 容易扫损，必须降低仓位 |
| HYPEUSDT | 高波动层 | 观察优先 | 波动强，先只做纸上交易 |
| ZECUSDT | 高波动层 | 观察优先 | 爆发行情多，必须防追高 |

周期配置：

| 周期名 | HFD 显示 | interval | 系统职责 | 是否可单独开仓 |
|---|---|---|---|---|
| 短期 | 短期 | 30m | 触发、入场、止损微调 | 否 |
| 中期 | 中期 | 1h | 位置、结构、清算目标 | 否 |
| 长期 | 长期 | 4h | 方向、趋势过滤、风险状态 | 否 |

开仓必须通过周期栈：

```text
长期方向通过
    |
    v
中期位置合理
    |
    v
短期触发确认
    |
    v
风控允许
    |
    v
纸上开仓
```

如果只有短期信号很好，但中期位置不好或长期方向相反，只记录观察，不开仓。

如果长期方向很好，但短期没有触发，也不开仓。

这条规则会少做很多单，但它能减少随机交易。少亏就是赚钱系统的第一步。

## 6. 模块说明

### 6.1 Signal Collector

职责：

- 定时拉取 HFD 指标。
- 拉取交易所行情。
- 保存原始响应。
- 记录采集状态。
- 按短期、中期、长期分别保存同一币种的信号快照。

要求：

- 请求失败自动重试。
- 每次采集生成唯一快照 ID。
- 不能覆盖历史快照。

### 6.2 Feature Builder

职责：

- 从原始指标中生成策略可用特征。
- 例如趋势方向、距离清算区、是否靠近成本带、是否出现 sweep。
- 生成周期栈特征，例如 long_bias、mid_context、short_trigger。

输出示例：

```json
{
  "symbol": "BTCUSDT",
  "timeframe": "30m",
  "trend_bias": "long",
  "near_cost_band": true,
  "near_liquidation_zone": true,
  "sweep_detected": true,
  "whale_confirmation": false,
  "exhaustion_score": 72
}
```

### 6.3 Strategy Engine

职责：

- 根据策略规则计算分数。
- 生成观察、开仓、平仓、忽略等决策。
- 保存策略版本。
- 同一策略要支持不同币种层级的参数模板。
- 同一策略要支持短期、中期、长期三套上下文输入。

策略版本示例：

- `trend_pullback_v0.1`
- `liquidity_sweep_reversal_v0.1`

币种参数模板示例：

- `core_asset`
- `mainstream_asset`
- `high_volatility_asset`

周期参数模板示例：

- `short_term_30m`
- `mid_term_1h`
- `long_term_4h`

### 6.4 Risk Engine

职责：

- 决定是否允许交易。
- 限制仓位。
- 限制单日亏损。
- 限制连亏。
- 控制系统是否暂停。

第一版风控规则：

- 单笔最大亏损：账户权益的 0.5%，纸上交易阶段可配置。
- 单日最大亏损：账户权益的 2%。
- 最大同时持仓：3 笔。
- 同币种最大持仓：1 笔。
- 连续亏损 4 笔后暂停。
- 信号缺失或接口异常时禁止新开仓。
- 高波动层币种的默认仓位减半。
- 高波动层币种的止损距离更宽，但仓位更小。
- 核心层币种允许更高权重和更稳定的参数。
- 短期交易允许更紧止损，中期交易允许更稳持有，长期交易允许更少频繁出场。

### 6.5 Paper Broker

职责：

- 模拟成交。
- 模拟手续费。
- 模拟滑点。
- 维护虚拟账户权益。

默认假设：

- 手续费：按交易所 taker 费率估算。
- 滑点：核心层低，主流层中，高波动层高。
- 成交价：用下一根 K 线开盘价或触发价加滑点。

### 6.6 Trade Journal

职责：

- 记录每笔交易的完整生命周期。
- 保存入场理由和出场理由。
- 保存信号快照引用。
- 支持复盘查询。

### 6.7 Dashboard

第一版只需要基础页面：

- 当前信号列表。
- 纸上持仓。
- 历史交易。
- 策略统计。
- 策略版本对比。
- 风控状态。

## 8. 策略模板

### 8.1 趋势回踩延续

做多条件：

1. 4h 趋势偏多。
2. 价格位于绿色趋势成本带上方。
3. 1h 回踩到机构均价、成本带或高换手节点。
4. 30m 出现企稳信号。
5. 上方有合理流动性目标。
6. 盈亏比至少 1:2。

做空条件相反。

参数差异：

- BTC、ETH：更强调稳定性和成本带。
- SOL、BNB、LINK、TON：更强调中期结构和资金持续性。
- DOGE、HYPE、ZEC：更强调短期 sweep、共振和快速收回，不追求长时间持仓。

周期差异：

- 短期：入场确认要快，容错低。
- 中期：优先看结构完整性。
- 长期：优先看方向正确，不急着追触发。

### 8.2 流动性猎杀反转

做多条件：

1. 价格下探多头清算区或散户止损点。
2. 出现 liquidity sweep。
3. K 线快速收回关键区间。
4. 多空失衡改善。
5. 趋势耗竭指标支持反转。
6. 止损可放在扫损低点之外。

做空条件相反。

参数差异：

- 核心层币种允许更高胜率筛选。
- 高波动层币种允许更大波动空间，但要求更快确认、更快止盈。
- 同一信号在不同币种层级上的通过阈值不同，不能一把尺子量到底。

建议默认参数框架：

| 层级 | 短期止损 | 中期止损 | 目标持有期 |
|---|---|---|---|
| 核心层 | 紧 | 中 | 中 |
| 主流层 | 中 | 中偏宽 | 中偏长 |
| 高波动层 | 宽 | 宽 | 短 |

## 9. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 信号重绘 | 高 | 保存实时快照，禁止使用未来数据 |
| 过拟合 | 高 | 策略版本化，样本量门槛，出样本验证 |
| 纸上交易过于理想 | 高 | 加入手续费、滑点、延迟、成交失败 |
| 连续亏损 | 高 | 连亏暂停，降低仓位 |
| API 异常 | 高 | 异常时禁止开仓，保留日志 |
| 实盘误触发 | 高 | 实盘默认关闭，需人工确认 |
| 策略频繁改动 | 中 | 每周复盘，每次只改一个变量 |
| 低流动性币种失真 | 中 | 币种分层，低流动性币种降低权重并更严格过滤 |
| 周期冲突 | 中 | 长期定方向，中期定位置，短期定触发 |

## 12. 成功标准

纸上交易成功标准：

- 至少 200 笔交易。
- 至少 6-8 周样本。
- 扣除成本后 ROI 为正。
- Profit Factor > 1.4。
- 最大回撤可接受。
- 连续亏损可被仓位管理承受。

模拟盘成功标准：

- 连续运行 2-4 周无严重执行错误。
- 订单状态和系统状态一致。
- 风控能正确拦截异常。
- Kill Switch 生效。
- 核心层、主流层、高波动层都能分别套用对应参数模板。

小资金实盘成功标准：

- 交易逻辑和纸上交易版本一致。
- 无异常订单。
- 无风控绕过。
- 小资金阶段最大亏损在预设范围内。
